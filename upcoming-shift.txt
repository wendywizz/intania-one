1. โมดูลที่แสดงใน Upcoming Shift  (มี 5 โมดูล)
================================================================================

  [1] Repair Computer   (แจ้งซ่อมคอมพิวเตอร์)   ไอคอน laptop
  [2] Absence           (ลางาน)                ไอคอน calendar-clock
  [3] Meeting           (ประชุม)                ไอคอน person.2.fill
  [4] Forgot Timestamp  (ลืมลงเวลา)             ไอคอน clock.fill
  [5] Examinar          (ตารางคุมสอบ)           ไอคอน checkmark.circle.fill

ทุกงานค้างแสดงเป็น "tile" หน้าตาและขนาดเดียวกันหมด เรียงเป็นแถวเดียว
เลื่อนแนวนอนได้ (ScrollView horizontal + snap เหมือนการ์ดข่าว)
ไม่ได้จัดกลุ่มตามโมดูล — ไอคอนกับ caption บนตัว tile บอกเองว่ามาจากโมดูลไหน

โครง tile:  บน = วงกลมไอคอนโมดูล + จำนวน
            ล่าง = label (ทำอะไร) + caption (โมดูลไหน)
ความกว้าง = min(190, 40% ของจอ) -> เห็น 2 ใบเต็ม + ขอบใบที่ 3 โผล่เป็นสัญญาณว่าเลื่อนได้
ทุกใบสูงเท่ากันเพราะ contentContainer stretch

โมดูลที่ "ไม่มี" ใน Upcoming Shift:
  - notice-repair (แจ้งซ่อมอาคาร/พัสดุ)   <- ไม่มีทั้ง Upcoming Shift และ Notification
  - news, person, my-profile, calendar, settings

-------------------------------------------------------------------------------
[1] REPAIR COMPUTER — สูงสุด 5 แถว
-------------------------------------------------------------------------------
เงื่อนไข: data.repairComputer.success = true
แสดงเฉพาะรายการที่ count > 0 (add() จะข้ามถ้า count = 0)
นับจาก data.repairComputer.tasks[] โดย match ด้วย task.key

 label        caption        key ที่ใช้นับ                ปลายทาง
 ------------------------------------------------------------------------------
 งานปัจจุบัน   แจ้งซ่อมคอม     user-current-job         /repair-computer/current-job
 งานใหม่       แจ้งซ่อมคอม     foreman-new-job          /repair-computer/foreman-new-job
 งานปัจจุบัน   แจ้งซ่อมคอม     foreman-running
                               + foreman-supply-approve  /repair-computer/manage-job
 งานใหม่       แจ้งซ่อมคอม     worker-new-job           /repair-computer/worker-new-job
 งานปัจจุบัน   แจ้งซ่อมคอม     worker-current-job
                               + worker-supply-wait      /repair-computer/worker-current-job

 หมายเหตุ: "งานปัจจุบัน" ของ Foreman และช่าง เป็นการรวม 2 key เข้าด้วยกัน
           ตัวเลขที่เห็นจึงเป็นผลรวม ไม่ใช่ค่าจาก key เดียว

 caption ไม่บอกบทบาท (ผู้แจ้ง/หัวหน้าช่าง/ช่าง) เพราะ active-summary ส่ง role
 มาแค่ค่าเดียวต่อบัญชี key ของบทบาทอื่นจึงเป็น 0 เสมอ -> ในทางปฏิบัติ
 tile ของแต่ละบัญชีไม่มีทางซ้ำ label กันอยู่แล้ว

3. กฎการแสดงผลรวม
================================================================================

การกั้นสิทธิ์
  - รายการ "อนุมัติ" ทั้ง 2 ตัว (ลา / ลงเวลา) ต้องได้ show: true จาก API ก่อน
    คนที่ไม่ใช่ผู้บังคับบัญชาจะไม่เห็นเลย
  - บทบาทใน Repair Computer ไม่ได้เช็คสิทธิ์ตรง ๆ แต่อาศัยว่า count = 0
    ทำให้รายการที่ไม่เกี่ยวกับผู้ใช้หายไปเอง

รูปแบบการแสดงผล
  - ทุก tile หน้าตาและขนาดเดียวกันหมด ไม่มี variant พิเศษ
    (เวอร์ชันเก่าเคยให้ tile ตัวสุดท้ายของแถวคี่ยืดเต็มความกว้าง
     พร้อมเปลี่ยนขนาดตัวอักษร ทำให้ item เดียวกันหน้าตาไม่เหมือนกัน)
  - tile จะถูกเพิ่มก็ต่อเมื่อ count > 0 เท่านั้น (ฟังก์ชัน add())
    ไม่ต้องเช็ค length > 0 ซ้ำที่จุดเรียกอีก
  - ลำดับคงที่ตามลำดับในโค้ด: repair -> absence -> meeting
    -> timestamp -> อนุมัติลงเวลา -> คุมสอบ  (ไม่ได้เรียงตามความสำคัญ)

กรณีไม่มีงานค้าง
  - ถ้า tiles.length === 0 จะ return null คือ section หายไปทั้งอัน
    ไม่แสดงการ์ดว่าง
  - แต่ตอน loading และ error ยังคง render อยู่ เพื่อไม่ให้ section กระพริบ
    เข้า-ออกระหว่างโหลด และเพื่อให้ปุ่ม "ลองใหม่" ยังกดได้

การรีเฟรช
  - โหลดตอนเข้าหน้า Home (useFocusEffect) และตอน pull-to-refresh
  - ทุก API ยิงขนานกัน ตัวไหน error จะ fallback เป็นค่าว่าง
    ไม่ทำให้ตัวอื่นพัง (เช่น exam ล่ม -> upcomingExams = [] แต่ส่วนอื่นยังแสดง)

5. จุดสีแดงบนเมนูโมดูล (เพิ่ม 2026-09-03)
================================================================================

หน้า Home มี 2 ที่ที่บอกว่ามีงานค้าง และทั้งคู่อ่านจาก "รายการเดียวกัน"
  1) แถบ tile "กิจกรรมที่รอดำเนินการ"  <- บอกว่ามีอะไร กี่รายการ
  2) จุดสีแดงมุมบนขวาของการ์ดเมนูด้านล่าง  <- บอกแค่ว่า "โมดูลนี้มีงานค้าง"

โค้ด
  buildShiftItems()   app/index.tsx  (ย้ายออกมานอก UpcomingShiftSection แล้ว)
    -> คืน ShiftItem[]  ซึ่งเป็นแหล่งเดียวของทั้ง 2 จุด
  ShiftItem.module    ฟิลด์ใหม่ = href ของการ์ดเมนูที่ item นั้นสังกัด
  MODULE_HREF         ตาราง href ของทุกโมดูล ใช้ร่วมกันกับ MENU_ITEMS
  pendingModules      Set<string> ใน HomeScreen = new Set(tiles.map(t => t.module))
  styles.menuBadge    จุดแดง 10px มุมบนขวา (ทรงเดียวกับ bellBadge ของกระดิ่ง)

เหตุผลที่ต้องมาจากรายการเดียวกัน
  ถ้าจุดแดงไปอ่าน activeSummary เองอีกรอบ จะมีโอกาสที่จุดแดงขึ้นแต่ไม่มี tile
  (หรือกลับกัน) เพราะเงื่อนไข add() ที่ count > 0 อยู่ในตัว buildShiftItems

โมดูลที่ "มีสิทธิ์" ขึ้นจุดแดง (6 จาก 9 การ์ด)
  /timestamp/calendar  /absence/pending  /meeting
  /repair-computer     /booking-room     /examiner

โมดูลที่ไม่มีทางขึ้นจุดแดง เพราะไม่มีแหล่งข้อมูลงานค้าง
  /notice-repair   (ไม่ได้อยู่ใน active-summary)
  /calendar        /person-search   (เป็นข้อมูลอ้างอิง ไม่มีงานให้ทำ)

หมายเหตุ ShiftItem.module ไม่เท่ากับปลายทางของ tile
  tile คุมสอบ  onPress -> /examinar   แต่ module = /examiner (การ์ดเมนู)
  tile ลืมลงเวลา onPress -> /timestamp/forgot-timestamp
                             แต่ module = /timestamp/calendar (การ์ดเมนู)
